# 이어하기 메모 (2026-10-28 집 PC → 클라우드)

학교 행사용 Profile Perfect 방식 추리 퍼즐 게임. 이 메모만 읽어도 이어서 작업할 수 있게 정리함.
자세한 규칙·결정은 `docs/계획서.md`(특히 11장 결정 1~41번, 7.1절 점검 결과).

## 파일 구조

| 파일 | 내용 |
|---|---|
| `index.html` `style.css` `game.js` | 게임 코드 (순수 HTML/CSS/JS, 외부 라이브러리 없음) |
| `stage.js` | 스테이지 데이터만. 맨 위에 작성법 주석. `submitUrl`(구글 시트 웹 앱 주소) 포함 |
| `images/` | 값 그림(SVG). 예시 7개(수학·체육·음악·미술·고양이·강아지·햄스터) |
| `fonts/Hakgyoansim_GeurimilgiR.ttf` | 학교안심 그림일기체 (6.3MB) |
| `docs/계획서.md` | 전체 계획·결정·점검 결과 |
| `docs/그림_가이드.md` | 값 그림 그리는 패턴(사물 하나·수량 반복·별 개수·색 원·기호 배지·작은 장면·얼굴·글자 알약)과 스타일 규칙 |
| `docs/구글시트_연결/` | Apps Script(`Code.gs`)와 설치 안내서 |

## 현재 상태

- 게임 기능 완성, 360×740 점검·더블클릭(file://) 확인 끝.
- 화면은 `<meta viewport width=360>`로 360px 배치를 기기 폭에 맞게 확대(어느 폰이든 같은 비율).
- 구글 시트 응모: 개인 Gmail 시트에 배포, "모든 사용자" 접근 확인됨(주소 GET → `{"ok":true,"message":"응모 받을 준비 완료"}`).
  시험 응모 1줄(이름 "시험응모")을 보냈으나 응답은 못 읽음 → 선생님이 "응모" 탭에서 줄이 생겼는지 확인·삭제 필요.
- GitHub 저장소 `salsaldoubledownmax/esekyoquiz`(공개) main에 올림.
  **GitHub Pages는 아직 안 켜짐**(Settings → Pages → Deploy from a branch → main / root). 켜지면 주소: https://salsaldoubledownmax.github.io/esekyoquiz/

## 남은 일

1. 선생님이 GitHub Pages 켜기 → 공개 주소에서 시작 화면·그림·글꼴·응모 칸 확인.
2. 시트 "응모" 탭에 시험 줄이 들어왔는지 확인(없으면 원인 조사: 응답을 GET으로 따라가며 다시 시험).
3. 실제 휴대폰(안드로이드 크롬·아이폰 사파리)에서 한 판씩 플레이.
4. 선생님이 진짜 스테이지(`stage.js`) 작성 → 단서마다 `cells` 적기.
5. 스테이지 값에 맞는 그림 SVG 생성(`docs/그림_가이드.md` 패턴대로) → `images/`에 넣고 `stage.js`의 `images`에 등록.
6. 공개 주소로 QR 코드 만들기.

## 작업 방식 메모 (사용자 선호)

- 사용자는 초등 교사. 한국어로, 쉬운 말로 설명.
- 변경 후에는 360×740 화면에서 직접 확인하고 결과를 표로 보고하는 방식을 선호.
- 결정이 바뀌면 `docs/계획서.md` 11장에 번호를 붙여 기록해 옴.
- 원작(Profile Perfect) 그림·로고를 그대로 베끼지 않고, 같은 느낌으로 새로 그림.
- 이모지 사용 금지(하트·자물쇠·체크 모두 SVG/CSS).
- 미리보기는 로컬에서 `node` 정적 서버(게임 폴더를 루트로)로 띄워 확인했음. file:// 은 미리보기 창이 못 엶.
