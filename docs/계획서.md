# 학교 행사용 추리 퍼즐 게임 개발 계획서

> 'Profile Perfect' 방식의 브라우저 논리 퍼즐(스테이지 1개). 학생들이 각자 휴대폰으로 플레이.
> 작성일: 2026-10-28

---

## 1. 원작 조사: Profile Perfect

| 항목 | 내용 |
|---|---|
| 개발/배급 | Lion Studios. iOS·Android 무료(광고·인앱 결제 포함) |
| 장르 | 논리 격자(logic-grid) 퍼즐을 '사건 파일·프로필' 느낌으로 포장한 추리 게임 |
| 격자 | 열 = 대상(사람·개·방 등), 행 = 속성(이름·성·국적·품종·위치 등) |
| 플레이 | 단서를 읽고 → 칸을 골라 → 속성 값을 지정. 맞으면 고정, 틀리면 목숨 감소 |
| 목숨 | 원작은 오답 2번이면 실패. 타이머 없음 |
| 단서 | 직접 단서("A는 미국인")와 관계 단서("가운데", "옆에", "~가 아니다")가 섞임. 간접 표현("음식 만드는 도구가 있는 방" = 부엌) 함정이 많음 |
| 자물쇠 | 일부 칸이 잠겨 있고, 일정 수의 칸을 맞혀야 열림 |
| 소거 | 한 행에서 나머지 칸이 다 풀리면 남은 칸은 소거로 확정되는 '행 소거' 풀이가 핵심 |
| 부가 요소 | 코인, 부스터(칸 자동 공개·단서 해설), 광고, 스토리 모드, 레벨 600개 이상 |

**가져올 것**: 열/행 격자, 탭→선택지 팝업, 정답 고정·오답 시 목숨 감소, 자물쇠 칸, 단계적 단서 공개, 함정 선택지.
**버릴 것**: 코인·부스터·광고·스토리·레벨 진행 등 부가 요소 전부(행사용 단일 스테이지이므로).
**바꿀 것**: 목숨 2개 → 3개(초등 저학년 고려). 단서 문장은 간접 표현을 줄이고 짧고 직접적으로.

> 참고: 원작의 화면·이름·그림은 쓰지 않는다. 규칙(장르 방식)만 참고하고, 제목·디자인·내용은 우리 학교 것으로 만든다.

## 2. 목표와 범위

- 학생이 휴대폰 브라우저로 링크(또는 QR)에 접속해 바로 플레이.
- 스테이지는 단 하나. 선택 화면·다음 스테이지 없음.
- 스테이지 내용(인물·속성·정답·단서)은 교사가 `stage.js`만 고쳐서 교체. 게임 코드는 건드리지 않음.

**완료 기준**: 7장의 5단계 확인 항목을 모두 통과하고, 실제 휴대폰 2대 이상(안드로이드·아이폰)에서 끝까지 플레이 가능.

## 3. 게임 규칙 (확정 명세)

### 3.1 상태
게임 상태는 아래 4가지가 전부다. '처음부터'는 이 4가지를 초기값으로 되돌리는 것.

| 상태 | 초기값 |
|---|---|
| `hearts` (남은 하트) | 3 (코드에 고정) |
| `filled[행][열]` (정답으로 채워진 칸) | `givens` 칸만 true |
| `checkedOrder` (체크한 단서 번호, 체크한 순서대로) | 빈 목록 |
| `phase` | `"playing"` (그 외 `"won"`, `"lost"`) |

파생 값(따로 저장하지 않고 매번 계산):
- **맞힌 칸 수** = `filled`가 true인 칸 수 (시작 칸 포함)
- 단서 i 공개 여부 = 맞힌 칸 수 ≥ `clues[i].at`
- 자물쇠 칸 열림 여부 = 맞힌 칸 수 ≥ `lock.at`

> 단서 공개·자물쇠를 따로 상태로 저장하지 않으므로 '다시 도전' 시 자동으로 처음 상태가 된다.

### 3.2 동작
1. 빈 칸(잠기지 않음) 탭 → 그 행의 `options`가 팝업으로 뜸.
   - 보기 창은 탭한 칸 바로 밑에 작게 뜨고, 같은 행에서 이미 정답으로 쓴 값은 빠짐(11장 2·4번).
2. 선택지 선택
   - 정답: 칸 고정(이후 탭해도 반응 없음). 맞힌 칸 수 +1 → 단서·자물쇠 재계산.
   - 오답: 하트 −1. 칸이 빨갛게 흔들린 뒤 빈칸으로 돌아감. 하트가 0이면 실패 화면.
3. 채워진 칸·잠긴 칸 탭 → 반응 없음.
4. **(변경)** 단서 카드는 탭해도 반응 없음. 단서의 `cells` 칸이 모두 정답으로 채워지면 자동으로 체크되어 흐려지고 맨 밑으로 감(판정과 무관). 아래 '체크를 끄면…' 항목은 더 이상 해당 없음.
   - 단서 카드 순서: **체크 안 한 공개 단서(원래 순서) → '?' 카드(원래 순서) → 체크한 단서(체크한 순서)**.
   - 체크하면 그 카드는 맨 뒤로 가고, 뒤에 있던 카드들이 앞으로 당겨짐.
   - 체크를 끄면 체크 안 한 단서들 사이의 원래 자리로 돌아감.
   - 순서가 바뀔 때 움직임 효과는 없음(즉시 재배치).
5. 모든 칸이 채워지면 완료 화면.
6. 완료·실패 화면의 '다시 도전' → 3.1의 초기 상태로.

### 4.1 그림·색 디자인 (2026-10-28 결정: 원작 느낌 파스텔 + 직접 그린 아기자기한 그림)
원작 그림은 옮기지 않고, 같은 분위기의 그림을 새로 그린다(모두 SVG, 이모지 없음).
- 인물 머리: 동그란 캐릭터 얼굴. 열 번호마다 머리색·머리 모양(짧은 머리·단발·양갈래·똥머리)·배경색이 자동으로 달라짐.
- 칸 값: `stage.js`의 `images`에 그림 파일이 있으면 그림 + 작은 이름, 없으면 글자만.
- 배경: 옅은 학교 소품 무늬(별·연필·책). 제목은 둥근 알약 모양 이름표.
- 격자: 흰 칸 + 옅은 선, 행 머리 연보라. 한 행을 다 맞히면 행 전체 연두색. 고르는 중인 칸은 하늘색.
- 자물쇠: 노란 자물쇠 + **앞으로 더 맞혀야 하는 칸 수**(맞힐수록 줄어듦).
- 단서: 격자 아래 "다 쓴 단서 N/전체" 알약 표시, 그 아래 나무 액자 안에 크림색 종이 카드(세로 목록). 카드 왼쪽 위 네모가 체크 칸.
- 숨은 단서: 하늘색 카드 + 남은 칸 수 배지 + '?' + "N칸 더 맞히면 공개".
- 완료 화면: 캐릭터들이 폴짝 뛰는 그림과 움직임(4단계에서 구현).

- 글씨: 본문 18px 이상, 칸 안 글자 16px 이상(긴 값은 줄바꿈). 시스템 기본 글꼴(외부 폰트 없음).
- 터치 영역: 칸·선택지 버튼·단서 카드·닫기 버튼 모두 최소 44×44px.
- 가로 폭: 격자는 `width: 100%` + 열 너비 균등 분배. 가로 스크롤 금지.
- 이모지 금지: 하트 = 인라인 SVG, 자물쇠 = CSS 도형(+숫자), 체크 = CSS 체크 표시(테두리 두 변을 45도 회전).
- 실패/완료 화면: 격자 위에 반투명 덮개(뒤의 격자가 비쳐 보임) + 가운데 상자(문구 + '다시 도전' 버튼).
  - 완료: "모두 맞혔어요!" / 실패: "하트를 모두 잃었어요"
- 자물쇠가 열릴 때: 고리가 위로 들리고 자물쇠가 흐려지며 사라진 뒤 빈칸이 됨(약 0.6초, CSS 애니메이션). 그동안 그 칸 탭은 무시.
- 카테고리 이름(행 머리): 폭 약 72px 고정, 길면 줄바꿈.
- 휴대폰 두 번 탭 확대·글자 선택 막음(`touch-action: manipulation`, `user-select: none`).

## 5. 데이터 형식 (`stage.js`)

```js
// ===== 스테이지 작성법 =====
// title      : 게임 제목
// people     : 인물 이름 목록 = 격자의 열 (왼쪽부터)
// categories : 속성 목록 = 격자의 행 (위부터). name = 행 이름, options = 팝업 선택지
//              (선택지는 인물 수보다 많아도 됨 = 함정)
// answer     : answer[행][열] = 정답. 반드시 그 행 options 안의 값
// givens     : 처음부터 채워 둘 칸 [행, 열]
// locks      : 잠긴 칸. cell = [행, 열], at = 맞힌 칸이 이 수 이상이면 열림
// clues      : 단서. text = 문장, at = 맞힌 칸이 이 수 이상이면 공개 (0 = 처음부터)
//              cells = 이 단서로 알아내는 칸 [[행, 열], ...]. 이 칸들이 다 맞으면 단서가 자동 체크됨
// images     : (선택) 값 → 그림 파일. 그림은 images 폴더에 넣음. 적지 않은 값은 글자만 보임
const STAGE = { ... };   // 사용자 제공 예시에서 hearts 항목만 뺌
```

> 하트는 3개로 고정(11-1 결정)이라 `hearts` 항목은 stage.js에서 뺀다. 남겨 두어도 무시된다.

### 5.1 데이터 검사 (게임 시작 시 1회)
교사가 직접 고치는 파일이므로 실수를 바로 알 수 있게 한다. 문제가 있으면 게임 대신 화면에 빨간 글씨로 무엇이 틀렸는지 표시.
- `answer` 행 수 = `categories` 수, 각 행 길이 = `people` 수
- 모든 정답이 그 행 `options` 안에 있음
- `givens`·`locks`의 [행, 열]이 격자 범위 안
- 같은 칸이 `givens`와 `locks`에 동시에 있지 않음
- 자물쇠 `at` ≤ (전체 칸 수 − 자물쇠 칸 수) — 열 수 없는 자물쇠 방지
- `images`에 적은 값이 어떤 `options`에도 있음(오타 방지)

> 퍼즐이 '논리적으로 풀리는지'는 코드가 검사하지 않는다. 교사가 8장 체크리스트로 직접 확인.

## 6. 코드 구조

| 파일 | 역할 |
|---|---|
| `index.html` | 뼈대. `stage.js` → `game.js` 순서로 `<script>` 로드(모듈 아님, `file://`에서도 동작) |
| `style.css` | 레이아웃, 흔들림 애니메이션, 하트·자물쇠·체크 모양 |
| `stage.js` | `const STAGE = {...}` 데이터만 |
| `game.js` | 상태·판정·그리기 |

`game.js` 주요 함수(단순하게 유지):
- `validateStage()` – 5.1 검사, 오류 문자열 배열 반환
- `reset()` – 3.1 초기 상태로 만들고 `render()`
- `correctCount()` – 맞힌 칸 수
- `render()` – 상태 → 화면 전체 다시 그림(하트·격자·단서·덮개). 규모가 작아 부분 갱신 불필요
- `openPicker(r, c)` / `closePicker()`
- `choose(r, c, value)` – 판정, 하트 처리, 흔들림, 완료/실패 전환

흔들림 처리: 오답 시 칸에 `.wrong` 클래스를 붙이고 애니메이션(약 0.5초)이 끝나면 제거. 그동안 입력을 막는다.

자물쇠 열림 처리: `render()` 직전의 맞힌 칸 수와 직후 값을 비교해, 이번에 기준을 넘은 자물쇠 칸에만 `.unlocking` 클래스를 붙여 애니메이션 후 제거. ('다시 도전' 직후처럼 처음부터 열려 있는 경우엔 효과 없음)

단서 순서: `checkedOrder`로 정렬해서 그림. 단서의 `cells`가 모두 맞으면 자동으로 목록 끝에 추가(`updateChecked`). 방금 충족된 단서는 `justChecked`, 날아오는 새 단서는 `incoming`으로 잠시 제자리를 지킴.

## 7. 단계별 구현·확인 계획

각 단계는 확인 항목을 통과한 뒤 다음으로 넘어간다.

| 단계 | 할 일 | 확인 |
|---|---|---|
| 1 | 격자·단서·하트 표시 | 3열×2행. 민준-과목 '수학'(그림) 채워짐. 민준-반려동물 잠김 + '4'(5 − 맞힌 1칸). 단서 3장 + '?' 1장("2칸 더 맞히면 공개"). 빨간 하트 3개. 인물 캐릭터 3명 **(완료)** |
| 2 | 칸 입력·판정·하트 | 서연-과목 '체육' → 고정. '미술' → 하트 1개 회색, 칸 흔들린 뒤 빈칸. 오답 3번 → 실패 화면 **(완료)** |
| 3 | 단서 공개·자물쇠·단서 체크 | 맞힌 칸 3개가 되는 순간 4번째 단서 공개. 5개가 되는 순간 자물쇠가 열리는 모션 후 빈칸. 그 전엔 잠긴 칸 탭 무반응. 단서는 자동 체크(19·38번) **(완료)** |
| 4 | 완료·실패 후 다시 도전 | 6칸 다 맞히면 축하 화면. 완료·실패 모두 '다시 도전' → 하트 3, 시작 칸만, 단서 원래 순서·체크 없음, 자물쇠 잠김(4), 단서 바 0 **(완료)** |
| 5 | 모바일 화면 | 360×740 스크린샷에서 가로 스크롤 없음, 팝업이 화면 밖으로 안 나감, 이모지 없음 **(완료)** |

## 8. 스테이지 작성 가이드 (교사용)

- 권장 크기: 인물 3~4명, 카테고리 2~4개. 1학년 대상이면 3×3 이하 권장. 인물 5명을 넘으면 칸이 좁아져 글씨가 작아짐.
- 값 길이: 칸에 들어갈 값은 4글자 이내 권장.
- 단서는 짧은 직접 문장으로. "~가 아니에요" 같은 부정 단서는 1~2개만.
- 작성 후 직접 확인:
  1. 공개된 단서만으로 풀 수 있는 칸이 항상 하나 이상 있는가(찍지 않고 끝까지 풀리는가)
  2. 각 단서의 `at` 시점에 그 단서가 꼭 필요해지는가
  3. 자물쇠 `at`에 도달 가능한가(잠긴 칸을 빼고도 그만큼 맞힐 수 있는가)
- 예시 스테이지 풀이 검증: 단서1·2 → 서연 체육, 지호 음악(맞힌 칸 3 → 단서4 공개) → 단서3 서연 강아지 → 단서4 지호 햄스터(5 → 자물쇠 열림) → 민준 고양이. 찍지 않고 풀림.
